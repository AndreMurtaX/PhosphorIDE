# The other end of a block -- roadmap item 22, under gtk2.
# Same case as steps-matching.txt; the keys are spelled the X way.
#
# TWO HALVES, AND ONLY ONE OF THEM IS OURS. SynEdit's own
# TSynEditMarkupWordGroup PAINTS the pair the moment the highlighter offers
# fmMarkup (usynphosphor.CreateFoldConfigInstance) -- so the boxes around the
# partner in these shots are SynEdit's, recomputed on every caret move and every
# edit, and no code of this repository draws them. What is ours is the JUMP and
# the sentence for the cases where there is nowhere to jump to.
#
# matching.bas: `function` on 7 pairs with `end function` on 13; the one-line
# pair is on 16; `next = 5` is on 20; `y = function + 1` on 24; the literal on
# 27; and the unterminated `while` on 32.
raise
wait 800

# THE PAIR, PAINTED. Ctrl+G puts the caret at 7:1, which is on `function`.
key ctrl+g
wait 600
type 7
key Return
wait 800
shot 420-the-pair-is-painted

# AND THE JUMP. Ctrl+Shift+M moves the caret to the partner and the status bar
# says which line it went to.
key ctrl+shift+m
wait 900
shot 421-jumped-to-the-end-function
# WHICH PARTNER IT FOUND. ActMatchBlockExecute writes `%s: line %d` from
# BlockName(M.Block) and M.ThereLine (umainform.pas:3133), so this is the pairing
# itself: `function` on 7 against the merged `end function` on 13.
text function: line 13

# AND THE CARET REALLY MOVED. Panel 0 is `%d: %d` over CaretLine/CaretCol
# (umainform.pas:4557); `end` starts at byte 1 of line 13. The message above is
# written AFTER the assignment, so it would still read `line 13` if the caret had
# not gone anywhere -- this is the half that says it did.
text 13: 1

# It is symmetric: from the terminator back to the opener.
key ctrl+shift+m
wait 900
shot 422-and-back-again
# SYMMETRIC. From the terminator back to the opener, and the number changes:
# a second press that had done nothing would still read `function: line 13`.
text function: line 7

# A PAIR THAT OPENS AND CLOSES ON ONE LINE still has a partner. Folding drops
# these because they hide nothing; matching keeps them.
key ctrl+g
wait 600
type 16
key Return
wait 600
key ctrl+shift+m
wait 900
shot 423-a-pair-on-one-line
# A BLOCK THAT OPENS AND CLOSES ON ONE LINE STILL HAS A PARTNER. This is the
# one number in the case that only the RAW scan can produce: `next` starts at
# byte 26 of `for i = 1 to 2 println i next`, and ScanFoldLine -- rule 6 -- drops
# both events of a line that folds nothing, so a match built on it would answer
# bmNone here and leave the caret on 16: 1.
text 16: 26

# --- AND THE THREE ANSWERS THAT ARE NOT A JUMP ---------------------------
# `next` as a variable, with nothing open above it.
key ctrl+g
wait 600
type 20
key Return
wait 600
key ctrl+shift+m
wait 900
shot 424-a-next-that-closes-nothing
# A TERMINATOR WITH NOTHING OPEN ABOVE IT IS A SENTENCE, NOT A JUMP. `next = 5`
# is a legal assignment; bmUnopened is what keeps it from closing the `for` on 16
# or the `while` on 32. Verbatim from umainform.pas:3140.
text this closes a for, and none is open

# `function` in an expression: not at a statement position, so not a block word.
key ctrl+g
wait 600
type 24
key Return
wait 500
key Home
key Right
key Right
key Right
key Right
key Right
wait 400
key ctrl+shift+m
wait 900
shot 425-function-in-an-expression

# A line that is a comment: not a block word either, and the same sentence.
key ctrl+g
wait 600
type 31
key Return
wait 600
key ctrl+shift+m
wait 900
shot 426-a-comment-is-not-a-block-word

# AN OPENER NOTHING CLOSES.
key ctrl+g
wait 600
type 32
key Return
wait 600
key ctrl+shift+m
wait 900
shot 427-a-while-that-is-never-closed
# AN OPENER NOTHING CLOSES. `while` on 32 runs to the end of the file, so its
# node keeps Partner = -1 with Kind = feOpen -- bmUnterminated, umainform.pas:3137.
# It is the opposite refusal to the one on line 20, and it names the block.
text this while is never closed
