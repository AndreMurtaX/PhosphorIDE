# Signature help. `mid$` is the case the whole table exists for: Reg.Add
# overwrites by signature and not by name, so it has two arities and both must
# show. The hint follows the caret, marks the argument being typed, and needs no
# dismissal -- closing the call moves the caret out of it.
#
# NO VOWEL AFTER A QUOTE. On an ABNT2 layout `"` is a DEAD KEY, so SendKeys
# composes it with whatever follows: `"a` becomes a diaeresis and both
# characters are lost. `"z` is safe. Measured on 2026-09-16, when the line came
# out as `s = mid$( bc",` and the editor was blamed first.
fixture lane345.bas

key ^{END}
wait 400
key {ENTER}
wait 300
type s = mid$(
wait 900
shot 101-first-argument

# THE HINT IS READABLE HERE AND IT IS NOT ASSERTED. Both halves of that are
# measurements from 2026-09-18 and both matter.
#
# It is a window of its own -- a THintWindow, owned by the form rather than a
# child of it -- so the instrument for it is `uiaany`, which walks every window
# the process owns, and not `uia`, which walks the form. Asked that way it came
# back in full, once:
#
#     Pane [HintWindow] mid$([string], number) | mid$([string], number, number)
#
# Both arities, first argument marked. That is exactly what this case exists for
# -- Reg.Add overwrites by SIGNATURE and not by name, so a `mid$` showing one
# line would be a table that had lost half of itself -- and it is what
# steps-signature-linux.txt claims "steps-signature.txt checks on Windows".
#
# AND IN THE OTHER ELEVEN RUNS THE HINT DID NOT APPEAR AT ALL: not in the UIA
# tree, not in a photograph of the window, not on the screen. `abs(` as well as
# `mid$(`; the first call typed in a session and the second; with a click into
# the text first and without; with the `(` in the same burst as the name and as
# its own keystroke 700 ms later.
#
# THE EDITOR IS NOT WHAT IS BROKEN, AND THAT WAS MEASURED BEFORE IT WAS WRITTEN
# HERE. Typed by hand into the running editor it appears EVERY time, follows the
# argument as each one is entered, and closes on the `)`. So what fails is the
# LANE: a window driven by SendKeys does not satisfy something
# RefreshSignatureHint (umainform.pas:4326) asks for, and the strongest candidate
# is its first guard, `Doc.Edit.Focused` -- because in the SAME runs Ctrl+Space
# opened its popup every time, and ActCompleteExecute is the one of the two that
# does NOT check it. A real synthetic click into the text area did not help,
# which is why this is still called a candidate and not a cause.
#
# So this case asserts the caret -- which is what proves the keys landed where
# they were aimed, including the dead-key trap in the header above -- and says
# the rest out loud rather than gating on something this driver cannot reach.
uiaeq 15: 10
type "z",
wait 900
shot 102-second-argument

uiaeq 15: 14
type 2, 3
wait 900
shot 103-third-argument

uiaeq 15: 18
# BRACED, because `key` is a chord and a bare ) is SendKeys syntax. The first
# version wrote `key )` and the parenthesis was never typed, so the hint stayed
# up and looked like a dismissal bug.
key {)}
wait 900
shot 104-closed-and-gone

# CLOSING THE CALL IS THE DISMISSAL. Nothing was pressed to put the hint away.
uiaeq 15: 19
