# A diagnostic you can see in the text -- roadmap item 24, under gtk2.

# blame.bas fails to compile and the host blames LINE 4.
#
# THE EDIT COMES LAST, AND THAT ORDER IS DELIBERATE. F9 saves before it runs, so
# an edit followed by another run would write the change into a checked-in
# fixture and leave the repository dirty after every pass. Editing last means
# nothing saves it: the driver kills the editor without saving, and the file on
# disk is the file in git.
#
# WHAT THIS CASE DOES NOT SHOW is the no-location branch -- `file not found:` and
# a `--check` warning carry no line, take AddProblem's other arm and mark
# nothing. That branch has no picture of its own: its evidence is a Problems row
# with no `(n)` in it, which this pane has shown since roadmap item 6.
raise
wait 800
shot 460-nothing-marked-yet

# RUN. F9 hands the file to the host, which refuses it and names line 4.
key F9
wait 4000
shot 461-line-4-is-marked

# THE HOST BLAMED LINE 4, IN WORDS. StartHost switches PagesOutput to TabOutput
# before the child starts, so the Output memo is SHOWING and no tab click is
# needed. AppendOutput adds the stderr line unprefixed and only a WHOLE line
# reaches it, which is what uphosphorrun's lines-not-bytes rule is for: half of
# this string is a diagnostic nobody can find. The host echoes the path it was
# GIVEN, which the lane passes absolute, so only the tail of it is named here.
text blame.bas:4: unexpected token in expression

# AND THE CARET WENT THERE. With exactly one Problems row RunnerFinished calls
# ListProblemsDblClick ITSELF, so this is the whole chain in one number:
# ParsePhosphorMessage found `:4: ` past the drive-letter scan, AddProblem
# recorded it, GotoSource clamped and set LogicalCaretXY, and RefreshStatus put
# Format('%d: %d') over CaretY/CaretX into panel 0. It said `1: 1` a moment ago.
text 4: 1

# THE MARK SURVIVES SCROLLING. To the end of the file and back.
key ctrl+End
wait 600
key ctrl+Home
wait 600
shot 462-still-marked-after-scrolling

# THE ROW THE EDITOR BUILT, which is a different claim from the line the host
# printed. AddProblem formats '%s(%d): %s' over ExtractFileName(Path), Msg.Line
# and Msg.Text -- so `blame.bas(4): ` exists only if the parser took the path and
# the line OUT of a message that carries three colons and left the text intact.
#
# THE TAB CLICK COMES FIRST, and it is not decoration. RunnerFinished found
# exactly one row, so it JUMPED instead of switching the pane -- the Problems
# page is alive, describable and NOT SHOWING, which is precisely the state
# `text` refused to accept from 2026-09-18. Asking without the click asserts
# nothing about what is on screen. The caption is plain `Problems`: only Call
# Stack and Variables grow a `(n)`, and only while a session is live.
tab Problems
wait 600
text blame.bas(4): unexpected token in expression

# A SECOND RUN CLEARS IT AND SAYS IT AGAIN. The file has not changed, so the

# THIS run and not an accumulation.
key F9
wait 4000
shot 463-a-second-run-marks-it-again

# AND EDITING THE MARKED LINE CLEARS IT, because a claim about text that has
