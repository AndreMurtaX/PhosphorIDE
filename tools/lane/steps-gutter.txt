# The hollow mark. Line 3 of lane345.bas is blank, so the host cannot bind a
# breakpoint to it; line 10 is a statement.
#
# TWO SHOTS, AND THE FIRST ONE MATTERS AS MUCH AS THE SECOND. Before a session
# there is no answer from any host, and both marks must be SOLID: the editor
# draws what the user meant rather than claiming a mark is dead on no
# information. Only after setBreakpoints answers does line 3 go hollow.
fixture lane345.bas

key ^g
wait 700
type 3
key {ENTER}
wait 500
key {F5}
wait 400
key ^g
wait 700
type 10
key {ENTER}
wait 500
key {F5}
wait 600
shot 51-before-any-session

# BEFORE ANY SESSION. Both marks are solid and no host has answered -- the
# negative below is what makes the positive after the stop mean something.
uiaeq 10: 1
uianot debug lane345.bas
key +{F9}
wait 5000
shot 52-stopped-line-3-hollow

# THE SESSION IS LIVE AND STOPPED. One frame, one variable in scope -- which is
# the host's answer arriving, and the answer is what turns line 3's mark hollow.
uia debug lane345.bas
uia Call Stack (1)
uia Variables (1)
unassertable the hollow ring and the solid dot are a TSynEditMark drawn into the gutter; no instrument on this platform reads one back, so what is checked here is that the host answered at all -- which is the only thing the drawing depends on
